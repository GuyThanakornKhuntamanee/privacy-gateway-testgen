# v2.2 Thai PDF and image rendering — design decision

Status: implemented on branch `feat/v2.2-thai-rendering`.

## Problem

The v2 renderers for `pdf`, `png`, `jpg` and `jpeg` were Latin-only by
construction: the PDF writer used the built-in WinAnsi Helvetica/Courier fonts,
and the raster renderer drew a 5x7 bitmap font. `_latin()` and `Canvas.text()`
raised on any character above U+007E, so Thai content was routed to
DOCX/XLSX/TXT and the attachment recorded `language_routing: pdf_latin_only`
(or `png_latin_only`, ...). That removed Thai from the two formats a Thai-first
Privacy Gateway most often sees.

Writing a Unicode text shaper (cmap, hmtx, GPOS mark attachment, Thai cluster
reordering) and a TrueType outline rasterizer to keep the project dependency-free
would be a fragile reimplementation of FreeType, HarfBuzz and a PDF font
embedder. The dependency policy already allows a third-party library when it
materially improves correctness, so the decision is to use mature renderers and
keep the *testcase* semantics (canonical text, spans, bounding boxes,
determinism) in our own code.

## Decision

| Concern | Choice | Why not the alternative |
|---|---|---|
| Raster text | Pillow (`ImageFont` + FreeType, `libraqm` shaping) | Our bitmap font cannot carry Thai at all; a custom outline rasterizer is a FreeType rewrite. |
| Native PDF | ReportLab (`Canvas` + embedded TrueType) | Hand-writing a Type0/Identity-H writer, ToUnicode CMap and subsetter is the fragile custom engine this iteration forbids. |
| PDF text extraction | pypdf | The previous regex extractor only understood `(literal) Tj` in Latin-1; Identity-H needs a real content-stream parser and ToUnicode mapping. |
| Font | Sarabun Regular + Bold, SIL OFL 1.1, vendored in `src/privacy_gateway_testgen/assets/fonts/` | Noto Sans Thai has no Latin glyphs, so mixed Thai-English would need per-run font fallback. Sarabun carries Thai, Latin, Thai digits and `฿` in one font, and is the common Thai document face. |

All three are downloaded at build time only; nothing at runtime touches the
network, and no system font is discovered or used. `renderers/fonts.py` resolves
the font through a package-relative path and raises `RendererUnavailable` when
the asset or `raqm` is missing instead of silently degrading.

## Ground truth stays ours

The renderer still receives a span-first `Doc`, so canonical text, entity values
and offsets exist before any bytes are produced. New in this iteration:

- every line keeps its own `(start, end)` range into the block text, so an entity
  bbox is measured from its *rendered prefix*, not from a character count
  multiplied by a fixed advance;
- Thai clusters (base consonant + combining marks) are never split by wrapping,
  and protected entity spans are never split at all — the canvas widens instead;
- raster rotation is applied to the recorded boxes, and they are stored as
  `bbox_space: "final"`;
- native PDF annotations stay `pdf_text` with real coordinates, scanned and
  hybrid image regions stay `pdf_image` with `source_type` set, and nothing is
  ever marked `ocr_verified`.

OCR is not run. Raster assets remain `verified_layout`, and the dataset exposes
`evaluation_requirement: ocr_required` for them so a benchmark harness can put
them in a separate subset instead of treating them as text-extraction cases.

## Determinism

- ReportLab runs with `invariant=1` (fixed creation date and document ID) and an
  explicit title/author/producer, so the same `Doc` produces identical bytes.
- PNG and JPEG come from Pillow's own encoders with fixed parameters; noise is
  generated from the case seed rather than Pillow's global RNG.
- Byte identity is guaranteed for one pinned dependency set on one platform.
  Across Pillow/ReportLab versions or OS builds, only content identity
  (extracted text, spans, boxes, case JSON) is claimed — never byte identity.

## Capability

`language_capability("pdf" | "png" | "jpg" | "jpeg")` becomes
`("th", "en", "mixed")`. `log` stays English-only because log bodies are
technical English by convention. The routing mechanism is kept so a future
renderer can declare a narrower capability without changing call sites.
